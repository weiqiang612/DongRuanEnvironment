# 原型与 UI 设计

## 总体设计总纲

本系统采用经典政务业务系统风格，以“稳重、清晰、可信、严谨、易用、可追溯”为核心原则。四端使用统一品牌、颜色、字体、组件和业务状态规范，并根据用户角色调整信息密度与交互方式。视觉服务于业务信息，不使用非必要装饰或炫技动效；在不新增后端业务模块的前提下，可用卡片、列表、统计图表和流程表达优化现有数据的呈现。

## 统一视觉规范

| 项目 | 规则 |
|---|---|
| Logo | 四端共用系统 Logo，仅以 `NEPS`、`NEPG`、`NEPM`、`NEPV` 副标题区分端别。 |
| 主色 | 使用政务蓝 `#1F5A94`，用于导航、主按钮和关键标题。 |
| 辅助色 | 使用低饱和环保绿 `#4C956C` 表达完成、正常与环保正向信息。 |
| 中性颜色 | 页面背景 `#F5F7FA`、主文字 `#1F2D3D`、次文字 `#606266`、边框 `#D9E1EA`；以白色和浅灰为主，避免大面积渐变背景。 |
| 字体与组件 | 优先使用微软雅黑、苹方等系统中文字体；使用统一线性图标、小圆角（4 至 6px）和弱阴影，以边框和背景层级区分模块。 |
| 动效 | 仅保留加载、切换和操作反馈所需动画，不使用炫技动画。 |

## 信息层级与页面骨架

所有页面按“待处理事项 → 异常、超时、预警 → 当前业务数据 → 历史及辅助统计”组织信息。标准页面骨架为：页面标题、关键状态或指标、查询条件、核心列表或表单、辅助统计和最近数据。NEPM 首页应优先展示待指派、已指派、已完成和已超时事项，再展示统计或最近上报。

## 当前页面

- `/`：PC 端系统统一入口，展示四端，分别进入对应登录页。
- `/neps/login`、`/nepg/login`、`/nepm/login`、`/nepv/login`：四端 PC 登录页共用同一视图组件、品牌图和山水背景；NEPS 输入手机号和密码，保留注册暂未开放提示并成功后跳转 `/aqiFeedback`；员工端输入网格员工号或管理员编号及密码，成功后进入对应最小落地页。
- 四端登录页在登录卡片左上角提供轻量“← 返回”链接，固定跳转 `/`，不依赖浏览器历史记录。
- `/nepg/portal`、`/nepv/portal`：登录态确认页，只说明后续业务功能尚未开放，不展示或伪造业务数据。
- `/nepm/portal`：NEPM 管理者工作台，使用“顶部系统栏 + 左侧分组导航 + 主内容区”的政务业务系统骨架，展示真实反馈与调度概览；管理端登录成功进入此页。
- `/aqiFeedback`：NEPS 公众工作台，提供“提交反馈”和“我的反馈”列表及省市选择；列表只展示当前登录公众的记录，待指派且未超时记录显示编辑、删除操作，其余状态只读；使用经典政务业务系统布局、状态语义和理解性错误提示。

### TASK-007 NEPM 原型映射

用户提供的七张 NEPM 原型定义管理端的视觉风格、导航层级和信息布局；原型中的日期、数量、人员、通知数与检测数据均为示意，不能作为前端默认业务数据或补充字段来源。

- 顶部系统栏固定展示系统标识、`NEPM 系统管理端`、当前管理员和返回统一入口操作；地区选择与通知图标仅作展示，除非后续任务明确其数据或交互来源。
- 左侧导航使用“工作台、公众反馈管理、任务调度管理、AQI 检测管理、预警管理、统计分析”六组结构。TASK-007 开放工作台、反馈列表/详情、任务分派/处理、超时预警和运营概览；检测结果、AQI 预警和完整统计入口显示“后续开放”，不得展示模拟数据。
- 工作台采用四张状态概览卡片、待办反馈表和超时优先事项的双栏布局。卡片只显示真实反馈与调度状态计数；原型中的环比和 AQI 分布图留待后续统计任务。
- 反馈列表提供状态、预估 AQI、地区、提交时间和关键词筛选，并以分页表格展示反馈。现阶段不提供区县筛选、最终 AQI 或处理人等无真实来源字段；未生成检测结果时以“后续产生”说明替代。
- 反馈详情使用“基本信息 + 处理流程 + 当前调度操作 + 指派日志”的两栏布局。原型中的检测结果卡片在 TASK-007 显示“网格员检测完成后生成”，不展示数值；调度区提供候选网格员选择和指派、重派或继续处理确认。
- 任务分派页突出筛选、任务表和“及时分派、超时优先、合理分配、跟踪处理”说明栏。任务处理复用相同调度能力与指派日志，不新增独立工作流。
- 超时预警页采用状态概览、筛选表单、超时反馈表和处置建议布局。只显示由既有 2 小时、24 小时规则得出的超时反馈；“已处理”仅指完成重派或继续处理操作，不创建 `alert_record` 或 AQI 异常预警。
- 检测结果与统计分析原型保留作为 TASK-008 至 TASK-010 的视觉参考；在 TASK-007 中仅显示不可操作的“后续开放”入口。

## 四端布局与信息密度

| 端 | 设计定位 | 布局与交互重点 |
|---|---|---|
| NEPS | 可信、简单的公众服务界面 | 突出“我要反馈”“我的历史反馈”“当前处理状态”“最终检测结果”，减少导航层级与专业术语。 |
| NEPG | 高效率的现场任务工具 | 优先显示当前任务、地址、任务详情、三项检测数据和检测时间，减少装饰并缩短一次提交路径。 |
| NEPM | 传统政务/B 端业务管理系统 | 使用顶部系统栏、左侧导航、面包屑、查询区、业务表格和详情/指派/重派操作；四端中信息密度最高。 |
| NEPV | 稳重的数据决策驾驶舱 | 可使用深蓝背景但避免霓虹或赛博化；仅展示已有的省分组统计、AQI 分布和趋势、检测数量、网格覆盖率与高等级预警。 |

### TASK-008 NEPG 原型映射

- `/nepg/tasks` 使用“我的任务 + 状态统计 + 全部/已指派/已完成筛选 + 任务卡片”布局；列表数量、状态、超时标识和地址均来自接口，不填充原型示例数据。
- `/nepg/tasks/{afId}` 展示反馈和任务事实。已指派状态显示三项输入与非负数提示；已完成状态展示系统最终等级、每项实测值、检测时间与预警生成结果，全部只读。
- 页面顶栏复用现有系统 Logo 资源，副标题为 `NEPG 网格员端`；提交中禁用按钮，并提供加载与错误反馈。

## 状态与业务颜色

### 任务状态

页面展示统一使用“待指派、已指派、已完成、已超时”，不得随意改为“处理中”“派单中”“办结”等其他名称。正常主流程固定为“待指派 → 已指派 → 已完成”。“已超时”是高优先级超时标识：待指派超过 2 小时，或已指派超过 24 小时仍未完成时显示；它不阻断管理员重派或继续处理。

待指派使用蓝色，已指派使用深蓝色，已完成使用绿色，已超时使用红色。状态颜色应采用浅色背景配业务色文字或边框，避免整块高饱和色造成阅读压力。

### AQI 等级

AQI 统一使用六级业务语义：优、良、轻度污染、中度污染、重度污染、严重污染。对应颜色分别为绿色 `#02E300`、黄色 `#FFFF00`、橙色 `#FF7E00`、红色 `#FE0000`、紫色 `#98004B`、褐红色 `#7E0123`；不得为页面配色而改变等级含义或颜色。页面以浅色背景、对应文字和边框呈现，最终 AQI 达到中度污染及以上时应突出预警标识。

## 信任感与可追溯表达

关键详情必须同时展示数据来源、状态和时间，并严格区分公众预估 AQI 与系统根据 SO₂、CO、PM2.5 实测结果计算的最终 AQI。任务完成后应展示最终等级、三项实测值和检测时间；不得将最终 AQI 表述为公众或网格员手工填写。

对于已有任务和指派数据，可用“反馈提交 → 管理员指派 → 网格员检测 → 系统计算 AQI → 任务完成或生成预警”的流程表达处理过程。该展示仅复用反馈、任务、检测结果、预警和指派日志数据，不新增业务模块。

## 交互规则

- 页面必须清晰显示状态、查询条件和可理解的错误提示；表单提交前提示缺失或越界字段。
- 公众端只展示本人反馈；任务已完成时才展示最终检测结果。管理员能处理重派或继续处理，决策端只读展示统计与预警。
- AQI 等级展示遵循 1 至 6 级：优、良、轻度污染、中度污染、重度污染、严重污染；中度污染及以上应有明显预警标识。
- 将可复用请求逻辑放入 `src/api/`，页面状态留在视图或 Pinia store。新增路由时同步更新 `src/router/index.ts`；表单修改必须与 `api_contract.md` 的请求字段保持一致。
- 所有关键操作必须满足“操作前明确、操作中有反馈、操作后有结果”：确认弹窗说明影响与保留数据，表单提供必填标识、格式与范围校验、加载状态、成功/失败反馈，并防止重复提交。

## 工程量控制

UI 优化不得扩大后端业务范围。允许基于已有反馈、任务、检测结果、预警和统计数据增加最近上报、状态分布、最新预警、数据卡片、同一数据的列表/卡片/图表切换和流程展示；不得因原型新增消息中心、聊天、实时轨迹、拍照取证、独立日志管理、地图调度、复杂工作流或新的业务角色。新增业务能力必须先创建任务并更新需求、接口和数据库设计。
